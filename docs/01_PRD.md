# BlinkWear Product Requirements

## Product And Problem

The current storefront presents BlinkWear as a marketplace to rent or purchase designer occasionwear, including lehengas, sherwanis, tuxedos, gowns, and pre-loved clothing. The public copy emphasizes local delivery, garment care, and seller listings. This records the product proposition expressed in the code; a formal problem statement, customer research, and success metrics are not present in the reviewed sources. Sources: [home metadata and homepage](../src/app/page.tsx), [root metadata](../src/app/layout.tsx), [seller entry page](../src/app/become-a-seller/page.tsx).

## Business Rules In Code

| Rule | Current source behavior | Sources |
|---|---|---|
| Listing types and visibility | Product listing type is `sale`, `rent`, or `both`; public catalog queries and RLS use active status. Seller/admin workflows include non-active states. | [product enums](../../mobile-app/mobile-app/supabase/schema.sql), [approval RLS](../../mobile-app/mobile-app/supabase/phase21_seller_product_approval.sql), [catalog query](../src/app/products/page.tsx) |
| Admin approval | Admin approval sets a pending product active. The intended phase34 behavior re-pends listing-content changes and image mutations; phase34 is review-only in its header and its current status guard raises on a seller-supplied status change. | [admin action](../../admin-panel/admin-panel/app/%28dashboard%29/products/page.tsx), [phase34](../../mobile-app/mobile-app/supabase/phase34_product_reapproval.sql) |
| Platform defaults | Seller commission 10%; buyer platform fee 5%; default delivery 70; pickup/return charge 70; default security deposit 20% of rental amount. Admin settings are stored in the singleton `platform_settings` row. | [settings schema/default row](../../mobile-app/mobile-app/supabase/phase12_pricing_commission_delivery.sql) |
| Per-listing price rules | A non-null per-product delivery charge overrides the platform default. A positive fixed security deposit overrides the default percentage; otherwise rental pricing uses the configured deposit percentage. Sale price uses discount price when present. | [web price calculator](../src/lib/pricing.ts), [mobile price calculator](../../mobile-app/mobile-app/src/utils/pricing.ts), [platform settings](../../mobile-app/mobile-app/supabase/phase12_pricing_commission_delivery.sql) |
| Buyer and seller fees | Buyer fee is calculated as a percentage of buy subtotal or rental amount; seller commission/payout snapshots use the seller commission percentage. | [web price calculator](../src/lib/pricing.ts), [order pricing schema](../../mobile-app/mobile-app/supabase/phase12_pricing_commission_delivery.sql), [paid order RPC](../../mobile-app/mobile-app/supabase/phase29_cart_uniqueness_and_database_audit.sql) |
| Rental period | Date span is inclusive. Past start dates and end-before-start are rejected; optional product min/max rental days are checked. Rental availability rejects overlapping ranges except cancelled/payment-failed bookings. | [date calculation](../src/lib/pricing.ts), [rental checkout function](../../mobile-app/mobile-app/supabase/functions/create-cashfree-rental-order/index.ts), [availability constraint/RPC](../../mobile-app/mobile-app/supabase/phase8_rental.sql) |
| Rental delivery and city | Rental booking code requires buyer and product city to match. The fulfillment lifecycle sets delivery/start timestamps and a due time based on rental days in 24-hour intervals. | [rental booking RPC](../../mobile-app/mobile-app/supabase/phase28_fix_create_paid_rental_booking_rpc.sql), [rental lifecycle](../../mobile-app/mobile-app/supabase/phase24_rental_state_consolidation.sql), [phase33 trigger](../../mobile-app/mobile-app/supabase/phase33_protect_rental_lifecycle_and_triggers.sql) |
| Cities | `platform_cities` stores active cities; SQL seeds Bhopal and Pune. Web city API falls back to those names if no active rows are returned; mobile theme and seller form also contain Bhopal/Pune constants. | [city schema/seed](../../mobile-app/mobile-app/supabase/20260929000000_phase25_system_foundation.sql), [web city API](../src/app/api/cities/route.ts), [mobile constants](../../mobile-app/mobile-app/src/constants/theme.ts), [seller onboarding](../src/app/become-a-seller/page.tsx) |
| Product availability | Buy/rent order creation checks active product status. Rental checkout also checks listing type, lock state, city/dates, and availability; database exclusion prevents overlapping active bookings. | [buy checkout function](../../mobile-app/mobile-app/supabase/functions/create-cashfree-order/index.ts), [rental checkout function](../../mobile-app/mobile-app/supabase/functions/create-cashfree-rental-order/index.ts), [order RPC](../../mobile-app/mobile-app/supabase/phase29_cart_uniqueness_and_database_audit.sql), [rental schema](../../mobile-app/mobile-app/supabase/phase8_rental.sql) |

Public policy copy and database rules are not fully aligned: the web cancellation page states 100%/90% and 100%/50% rental refund windows, while the database singleton defaults are 100%/0% before acceptance and 80%/20% after acceptance, with post-dispatch cancellation disabled. The published rental page also describes delivery/return timing and late fees not fully represented by the default database values. Sources: [cancellation page](../src/app/cancellation-policy/page.tsx), [rental page](../src/app/rental-policy/page.tsx), [cancellation schema](../../mobile-app/mobile-app/supabase/20260929000000_phase25_system_foundation.sql), [late-fee fields](../../mobile-app/mobile-app/supabase/phase16_order_lifecycle.sql).

## OPEN QUESTIONS

1. What is the formal customer problem, primary persona, and success metric? The code contains marketplace positioning but no product brief or metrics. Sources: [homepage copy](../src/app/page.tsx), [seller entry page](../src/app/become-a-seller/page.tsx).
2. Are Bhopal/Pune the only supported launch cities, or should all active `platform_cities` be available consistently across clients? Mobile currently has a fixed two-city constant while web reads the table. Sources: [mobile city constants](../../mobile-app/mobile-app/src/constants/theme.ts), [web cities API](../src/app/api/cities/route.ts), [platform cities table](../../mobile-app/mobile-app/supabase/20260929000000_phase25_system_foundation.sql).
3. What is the canonical buyer fee for a purchase, and should purchase orders include pickup/return charge? Mobile buy pricing includes pickup/return; web buy pricing and the create-buy Edge Function omit it, while the final RPC adds the metadata value during total verification. Sources: [mobile pricing](../../mobile-app/mobile-app/src/utils/pricing.ts), [web pricing](../src/lib/pricing.ts), [buy-order Edge Function](../../mobile-app/mobile-app/supabase/functions/create-cashfree-order/index.ts), [paid-order RPC](../../mobile-app/mobile-app/supabase/phase29_cart_uniqueness_and_database_audit.sql).
4. Which cancellation, deposit-refund, and late-fee policy is authoritative when the public policy page differs from database defaults/lifecycle fields? Sources: [cancellation page](../src/app/cancellation-policy/page.tsx), [refund page](../src/app/refund-policy/page.tsx), [cancellation schema](../../mobile-app/mobile-app/supabase/20260929000000_phase25_system_foundation.sql), [rental lifecycle](../../mobile-app/mobile-app/supabase/phase33_protect_rental_lifecycle_and_triggers.sql).
